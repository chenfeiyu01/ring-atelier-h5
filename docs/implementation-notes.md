# 实现说明

## 几何与输入

根据 750×750 的视频及补充截图重建。戒托是连续带底槽带，截面沿周向翻转 360°，不能增加固定的内筒。戒圈中轴半径 1.30；20 颗银珠半径 0.195；槽内 / 外半径 0.205 / 0.250。尺寸为相对单位，并非工程数据。

钻石为自行生成的闭合圆形明亮式切割：1 个台面、8 个星面、8 个主冠面、16 个上腰面、8 个主亭面、16 个下腰面，共 57 个光学切面，另有 16 个腰棱面。台面宽比 56%，冠高 15.75% 直径，亭深 42.5% 直径，是展示用比例，不宣称 GIA 切工等级。基础腰围半径 0.29，所有光学面保持平面法线。此前公开版的 10 颗槽带钻石检查保留在 diamond-validation.json；当前本地版槽带只支持银珠，基础钻石用于四爪中心石与两款的固定小排镶。

本地新增四爪单石与三线抱珠，通过 GLB 的 inlay_slot extras 记录主石和固定小钻的位置、方向与大小。四爪提供银珠、钻石和独立椭圆阶梯蓝宝石；另外两款仅银珠。三线在珠处形成等边三角形，两条平面条带固定排镶，一条抛光条支撑；三条各自延伸，只在对侧一个点汇合。模型数据见 mounting-validation.json。

金属预设的线性 baseColor 代表导体 F0，metalness 固定为 1。18K 黄金、白金（常见镀铑白色黄金）、玫瑰金和铂金各有独立反射参数；铂金与银采用公开 RGB 反射率，合金与镀铑外观为展示近似，未绑定特定厂商合金配方。换金属只更新戒托材质，银珠材质不变；追踪器更新材质后重新采样，时间历史清空。参数来源见 README。

## 光影与优化

Three.js WebGL + 自生成线性 HDR 环境 + ACES。使用 [three-gpu-pathtracer](https://github.com/gkjohnson/three-gpu-pathtracer) 0.0.24，保持现有 H5 WebGL 路线；上游主线已转向 WebGPU，不能无检查直接升级。当前采用实时预览与静态精细路径追踪；交互预览使用独立宝石光路，没有自动旋转。

- 最终完整分辨率 192 样本，8 次一般反弹，另有 12 次透射内部遍历。镜面主导的 HDR 场景使用 BSDF 方向采样，关闭每个表面的环境 MIS 阴影射线。没有直接场景灯光，钻石小型灯板同样属于 HDR 环境。
- `src/jewelry-preview.js` 管理实时预览。金属预览材质同步原 PBR 材质的颜色、粗糙度与环境强度，使用按环境缓存的 PMREM。`src/gem-preview.js` 对各独立切型建立共享的局部空间 BVH，几何副本用于构建，保留原模型索引与路径追踪输入不变。
- 宝石预览采用最多 8 次内部求交，按菲涅耳权重累积每次出射到 HDR 环境的贡献，并继续跟踪内部反射；全内反射不产生错误出射方向，达到遍历上限时舍弃残余能量。钻石每帧分别计算 RGB 三波段，蓝宝石使用单一折射率和 Beer-Lambert 吸收。没有随机 RGB 选择和时间累积，新显露表面也不会出现低采样彩色噪声。宝石出射仍近似查询环境，预览不包含完整场景焦散或所有多次互反射。
- 同一切型、同一材质的宝石使用 InstancedMesh 合批，126 颗排镶共享着色器、BVH 和一次绘制。世界变换、各实例尺度和介质内的世界距离分别参与计算；切换模型时释放旧实例缓冲。
- 同材质的镶爪、戒臂和银珠在独立预览缓冲中合并几何与固定变换，不修改原模型。四爪、三线、槽带的主几何绘制分别为 3、4、2 次；新增反射 pass 分别为 2、3、2 次，最后再执行一次全屏输出。无 Float32 线性过滤扩展的设备使用最近邻环境采样，避免不完整纹理导致黑屏。
- `src/metal-reflections.js` 对不透明首饰构建独立 BVH，按复杂度分配约 2.4 万或 4.8 万像素计算一次确定性镜面求交，以命中表面法线、金属 F0、菲涅耳和合成粗糙度近似二次入射辐射。用深度引导的 3×3 重建送入完整分辨率的 PBR；不是降低整幅预览的分辨率。银珠与微小镶嵌粒使用较粗球体，固定版本的槽带从 640×164 网格抽取 160×82 求交代理，校正与原法线一致的绕序；原始显示网格和路径追踪网格不变。代理与有限反弹会损失极细的反射，完整静态路径追踪仍负责最终结果。
- `src/surface-history.js` 在完成 192 样本后保存线性 HDR 与真实网格深度。预览的 MSAA 深度用于重建当前位置并投影到旧视角，遮挡不匹配或新露出的表面不读取旧颜色；视角 0.35° 至 2.5° 之间淡出，缩放约 0.1% 至 2.5% 之间淡出。历史复用只在全屏合成阶段执行，宝石 shader 不增加历史采样或寄存器负担。切换材质、灯光、模型或尺寸后立即清空有效标记。
- 摄影棚改用有限柔光箱、条形反光板和暗区，柔化边缘以呈现曲面的高光梯度；光源生成和 PMREM 仍按环境缓存，转动相机不重新计算灯光。
- 按住鼠标或触摸期间只绘制预览，不执行全场景路径追踪。最后一次视角变化 180ms 后且输入已结束才开始累积。预览缓存到带多重采样抗锯齿的半浮点缓冲，相机、材质、灯光或尺寸变化后才重绘。
- 32 样本前持续显示稳定预览，32 至 128 样本之间按 smoothstep 在线性 HDR 空间混合，统一执行一次曝光、ACES 与 sRGB 输出。最终去噪仍从 sigma 2 / threshold 0.14 渐变到 sigma 1.25 / threshold 0.10；filterGlossyFactor 0.20。16 样本以后每帧计算两个样本，不降低最终采样上限。
- 不再运行低分辨率的全场景路径追踪与旧运动去噪。`src/motion-denoise.js` 保留为历史实现，当前查看器不导入或执行它。
- 初次加载在实时预览可用后即可显示并操作，精细采样在后台继续。切换镶嵌只保留一个追踪器，重建场景 BVH 与预览实例；灯光、尺寸或材质变化立即显示新预览并重新采样。
- 像素比最高 1.8，总像素约 220 万；隐藏页面暂停，完成采样后不再绘制。环境和切型 BVH 缓存随查看器销毁释放。

## 钻石光学

`src/diamond-optics.js` 在固定版本着色器的明确锚点加入专用抛光介质分支；锚点不匹配则报错。真实切面决定光线方向；按菲涅耳概率选择反射或折射，显式处理全反射，继续追踪内部交互及环境照明。表面并非银色金属，也没有用透明度叠加模拟折射。

路径第一次进入钻石时选择一个 RGB 波段，并在整条路径保持同一波段。采用 2.410 / 2.417 / 2.435 的近似折射率，三通道等概率采样并进行权重补偿。这是三波段色散近似，不能声称完整光谱色度学或精确宝石光学测量。白色灯板经过光线路径形成颜色分离，不使用彩虹贴图。参考：[GIA 钻石资料](https://www.gia.edu/diamond)、[GIA 切工研究背景](https://www.gia.edu/diamond-cut/cut-grade-research-background)、[PBRT 介质 BSDF](https://www.pbr-book.org/4ed/Reflection_Models/Dielectric_BSDF)。

## Apple WebKit

旧版已在 Safari 复现清漆导致整件戒指全黑；钻石联合着色器在本机 Chromium 也复现了相同问题，单独关闭该层后恢复。当前四种金属预设统一采用不叠加透明清漆的导体表面，clearcoat=0。上游同类记录：[issue 711](https://github.com/gkjohnson/three-gpu-pathtracer/issues/711)。

新增钻石时，在桌面 Safari 实际复现“金属正常、钻石不透光”。分别关闭色散、跳过 sheen、使用有限吸收距离均未解决；改为专用抛光介质分支后恢复。上游也有 [WebGL 通用透射问题](https://github.com/gkjohnson/three-gpu-pathtracer/issues/682)。此修复绕过问题分支，不宣称已定位浏览器编译器的底层缺陷。着色器编译失败会停止并显示错误，不能继续显示采样完成。
